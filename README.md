# Snake DQN

A Deep Q-Network (DQN) agent that learns to play the classic Snake game, built with Pygame and PyTorch. The training loop is adapted from the [Official PyTorch DQN Tutorial](https://docs.pytorch.org/tutorials/intermediate/reinforcement_q_learning.html), but it runs on a custom Snake environment instead of a standard `gymnasium` benchmark like CartPole.

## Environment Dynamics (`game.py`)

The `s_env` class implements the Snake game with the following mechanics:

- **Board:** A `480 x 480` window, which is a `24 x 24` grid of cells. The snake and fruit are `20 x 20` blocks, and the snake moves `20` pixels (one cell) per step.
- **Initial state:** The snake starts in the center of the board (`240, 240`) heading right, with a length of 1. The fruit spawns at a random grid-aligned position that is not the snake's starting cell.
- **Action space:** Four discrete actions: `0` = right, `1` = left, `2` = down, `3` = up. Actions that would reverse the snake directly into itself (for example pressing left while heading right) are ignored, and the snake keeps its current direction.
- **Observation (12 binary features):**
  - *Danger* (4): whether moving right / left / down / up from the current head position would hit a wall or the snake's body
  - *Heading* (4): the snake's current direction of travel (right / left / down / up)
  - *Fruit direction* (4): whether the fruit is to the left / right / above / below the snake's head
- **Growth:** Eating the fruit grows the snake by one segment and respawns the fruit at a random grid-aligned cell that is not occupied by the snake.
- **Termination:** The episode ends when the snake hits a wall or its own body.
- **Truncation:** Episodes are truncated after `2000` steps.
- **Rendering:** The game is drawn on every step, with the clock capped at `1000` ticks per second. A line in `game.py` (`SDL_VIDEODRIVER = "dummy"`) is commented out; enabling it runs Pygame without opening a window, which can speed up training.
- **Logging:** `reset()` prints the total reward of the episode that just finished.

### Reward Structure

| Event | Reward |
|-------|--------|
| Eat fruit | `+10.0` |
| Hit wall or self | `-10.0` |
| Step that moves closer to the fruit (Manhattan distance) | `+0.1` |
| Step that moves farther from the fruit (or keeps the distance the same) | `-0.15` |

The small per-step rewards are shaping rewards. They guide the agent toward the fruit before it has learned to eat it reliably. Moving away is penalized slightly more than moving closer is rewarded, so the agent is discouraged from wandering in circles.

## DQN Architecture & Hyperparameters (`dqn.py`)

The network is a feedforward Q-network. It is trained with Huber (SmoothL1) loss, epsilon-greedy exploration, a replay buffer, and a target network that is updated by Polyak averaging (soft updates).

| Setting | Value |
|---------|-------|
| Network | `12 -> 128 -> 128 -> 4` (ReLU) |
| Loss / optimizer | Huber (SmoothL1) loss, AdamW with AMSGrad (`LR = 1e-4`) |
| Gradient clipping | Clipped by value at `100` |
| Discount (`GAMMA`) | `0.99` |
| Batch size | `128` |
| Replay memory | `50,000` transitions |
| Exploration | Epsilon-greedy, `0.9 -> 0.01`, exponential decay constant `30,000` steps |
| Target update | Polyak averaging, `TAU = 0.005` |
| Episodes | `60,000` with CUDA/MPS, otherwise `2,000` |

Notes on how it works:

- The input size is taken directly from the environment (`n_state = len(state)`), and each state is wrapped into a 2D tensor with `.unsqueeze(0)` so it has the batch dimension the network expects.
- When the episode terminates (wall or self collision), `next_state` is stored as `None`. The future value for that transition is then treated as `0`.
- Truncation at 2000 steps ends the episode but is not treated as a terminal state, so the agent still bootstraps from the next state.
- The script selects `cuda` if it is available, otherwise `cpu`. The number of episodes is chosen by checking for CUDA or MPS.

## Scripts

- **`a.py`**: An extra script in `snake/`. I haven't seen its contents, so it isn't documented in detail here.
- **`game.py`**: The Snake environment (`s_env`), with `reset()` and `step(action)` methods that return `(observation, reward, terminated, truncated)`.
- **`dqn.py`**: Trains the agent with the hyperparameters above. The policy network weights are saved to `snake_dqn.pth` once, at the **end** of training, after all episodes finish.
- **`dqn_plot.py`**: Same training loop, but it plots the reward of each episode live with Matplotlib, along with a 100-episode moving average. It does not save the model.
- **`test.py`**: Loads a trained model and plays up to `2000` games with a greedy policy (no exploration), printing the fruits eaten per episode and the average at the end.

### Status of `dqn_plot.py`

> **The plot version has not been updated yet.** It still uses the older settings and therefore does not match `dqn.py` or the current `game.py`:
>
> | Setting | `dqn.py` (current) | `dqn_plot.py` (old) |
> |---------|--------------------|---------------------|
> | Network | `12 -> 128 -> 128 -> 4` | `12 -> 256 -> 256 -> 4` |
> | Learning rate | `1e-4` | `1e-3` |
> | `TAU` | `0.005` | `0.001` |
> | Epsilon decay | `30,000` | `2,500` |

The environment is still created from `game.py`, so the game itself runs at `480 x 480`, but the training settings differ. Results from `dqn_plot.py` are therefore not directly comparable to `dqn.py` until it is brought in line.

## Usage

Run all commands from inside the `snake/` folder, because the scripts import `game.py` directly and `snake_dqn.pth` is saved to the current folder.

Train the agent:

```bash
cd snake
python dqn.py
```

Train with a live reward plot (old settings, see the note above):

```bash
cd snake
python dqn_plot.py
```

Watch a trained agent play (pass the model path):

```bash
cd snake
python test.py snake_dqn.pth
```

Close the Pygame window to stop the test run.

> **Note:** `test.py` must build the same network as the one that produced the weights. Since `dqn.py` now uses `12 -> 128 -> 128 -> 4`, check that the `DQN` class in `test.py` uses the same layer sizes, or loading `snake_dqn.pth` will fail with a size mismatch.
